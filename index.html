Die, See, Level (PlayStation Career Pathways Game Jam)

🏆 1st Place, Ratchet It Up! Game Jam

A first-person action game set inside a giant cube, where the player can shift gravity to any of the six walls at will. Every physics object and every enemy falls toward the new floor, turning each fight into a puzzle of positioning and timing. Built by a small team over several weeks, the game took first place in the jam.

I designed and built the enemy AI and combat systems:

  • Enemy AI: enemies sense the player, chase them across the arena, and attack when in range, all working on top of the team's dynamic gravity system.
  • Combat: line-trace player attacks with a cooldown, a damage pipeline with enemy health and death, and player health.
  • Animation: Blend Spaces, Animation Blueprints, and Anim Montages for smooth locomotion and attacks.
  • HUD: a live health bar bound to the player's state.

Unreal Engine 5 · Blueprints · Mixamo · Git/GitHub

Jello Cube: Mass-Spring Physics Simulation

Course project · USC

A real-time simulation of an elastic jello cube, modeled as a 3D mass-spring network of 512 point masses. The cube stretches, squashes, and wobbles as it bounces around inside a box, driven by Hooke's law, damping, and numerical integration of Newton's equations of motion. The course provided the rendering and camera code; I implemented the physics:

  • Mass-spring network: structural, shear, and bend springs connecting an 8×8×8 grid of masses, with elastic and damping forces computed for every spring.
  • Numerical integration: runs with both explicit Euler and 4th-order Runge-Kutta (RK4), with stiffness, damping, and time step tuned to keep the simulation stable.
  • Collisions: detection and penalty-based response against all six walls of the bounding box.
  • Force fields: arbitrary external force fields defined on a 3D grid, sampled at each mass point with trilinear interpolation.

C++ · OpenGL · GLUT · Physically based animation

Motion Capture Interpolation: Euler Angles vs. Quaternions

Course project · USC

Rebuilding human motion from sparse keyframes. Starting from 120 fps optical motion capture of dancing and martial arts, I kept only a few keyframes, reconstructed every missing frame with four different interpolation methods, and measured how closely each one matched the original performance. The course provided the motion capture player and file parsing; I implemented the interpolation:

  • Euler interpolation: Bezier interpolation of joint angles across the full skeleton hierarchy, compared against the provided linear version.
  • Quaternion interpolation: conversions between Euler angles and quaternions, spherical linear interpolation (SLERP), and Bezier SLERP using Shoemake's control-point construction.
  • Analysis: plotted joint angles over time for each method against the original data, comparing smoothness, accuracy, and artifacts such as gimbal-related jumps in Euler space.

In the video, the green skeleton is the original motion capture and the red skeleton is rebuilt with Bezier SLERP from one out of every 41 frames.

C++ · OpenGL · FLTK · Quaternions · Motion capture (ASF/AMC)

Inverse Kinematics with Skinning

Course project · USC

Interactive character posing: the user grabs a handle on the character, drags it, and the whole body follows naturally. The system solves for joint rotations across the skeleton hierarchy in real time and deforms the character's mesh to match. The course provided the mesh loading, rendering, and user interface; I implemented the animation pipeline:

  • Forward kinematics: built each joint's local transform from Euler angles and traversed the skeleton hierarchy to compute global and skinning transforms.
  • Linear blend skinning: deformed every mesh vertex as a weighted blend of the transforms of the joints that influence it.
  • Inverse kinematics: computed the Jacobian of the handle positions with automatic differentiation (ADOL-C) and solved a Tikhonov-regularized least-squares system with Eigen, balancing accuracy against stable, natural-looking poses.

C++ · OpenGL · Eigen · ADOL-C · Linear algebra

Software Rasterizer: The GPU Pipeline in C++

A from-scratch software implementation of the graphics pipeline that GPUs run in hardware, written in C++ without any graphics API. Given raw vertex data and shader functions, it produces the final image pixel by pixel, which meant building every stage that OpenGL normally hides.

  • Vertex processing: runs a vertex shader on each vertex, then performs the perspective divide into normalized device coordinates.
  • Triangle rasterization: converts each triangle into the pixels it covers using barycentric coordinates.
  • Attribute interpolation and shading: interpolates per-vertex data across each triangle and runs a fragment shader to color each pixel.
  • Depth testing: a z-buffer that resolves which surface is visible at every pixel.

C++ · Graphics pipeline · Rasterization

Underwater Caustics and God Rays

An underwater scene recreating two signature effects of light passing through water: the web of bright caustic patterns rippling across the seafloor, and the shafts of light, or god rays, cutting down through the water.

  • Caustics: procedural Worley (cellular) noise using the F2 − F1 distance, which naturally forms the thin, bright ridges of real caustics. The noise is generated as a 3D volume, sharpened with a power curve, and displayed as 2D texture slices.
  • God rays: volumetric light shafts rendered with ray marching, accumulating light along each view ray through the water.

Unity · C# · Procedural noise · Ray marching
